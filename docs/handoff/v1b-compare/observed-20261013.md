活动统计只覆盖 pointerdown 到 presentation idle，后面的 1,500ms 观察窗口独立记录，未稀释活动帧百分位。`firstFrameMs` 是 rAF 与 pointer 时间戳差，不解释为输入延迟。

Chromium 正常速度实测：响亮出牌落桌 943ms / busy 2,118ms；安静出牌 946 / 3,280ms；固定回放最长安静文案 940 / 4,032ms。平静月末 busy 3,511ms，多丑闻 10,688ms，Copycat 11,308ms，换季 8,059ms，冬季结局 1,830ms。样例本身的事件与完整文案决定总时长；没有缩短阅读、自动选牌或增加月份。

4× 慢帧集中在 `publish`：平静月末 83.4ms / 同期 JS 长任务 76ms；多丑闻 108.3 / 71ms；Copycat 75.1 / 63ms；换季 100 / 84ms；冬季 100 / 59ms。响亮出牌后的 75ms 长任务发生在 busy 结束后，不能算入活动帧。旧 CPU profile 指向首次半色调绘制/PNG 编码；新的发布长任务还需单独 profile，不能仅凭重合认定都是图片生成。

## 未采纳的绘制探针

以下仅在测量页面临时注入 CSS。改变画面的探针不用于功能、视觉或流畅度验收。每项均保留同名 JSON 和 `-power.json`，没有用较好的结果替换正式测量。

| 探针 | Firefox calm / frenzy p95 | WebKit calm / frenzy p95 | 判断 |
|---|---:|---:|---|
| `compact-planes`：缩小空白透视容器 | 66.66 / 75 | 140 / 155 | 未改善，不采纳 |
| `ambient-layer`：环境物件单独合成 | 66.68 / 91.68 | 283 / 216 | 更慢，不采纳 |
| `no-ambient`：隐藏环境动画 | 33.34 / 33.34 | 87 / 95 | Firefox 部分改善，WebKit 仍慢；会删视觉，不采纳 |
| `flat-presentation`：去掉透视 | 33.32 / 41.68 | 88 / 98 | 未根治且违反桌面空间，不采纳 |
| `no-grain`：去掉报纸 SVG 噪声纹理 | 33.34 / 50 | 83 / 92 | 收益有限且改变画面，不采纳 |

查进程时没有遗留 Firefox/Chromium/WebKit 测量进程。不能据此把剩余成本归咎于浏览器驱动，也不能声称真实 Safari/iPad 已通过。仍需定位发布的 JS 长任务，并验证 Firefox/WebKit 的绘制成本与真实设备表现。

## 复现

先构建；停止所有正确性检查。Windows 可运行 `./tools/perf-observed.ps1 -Name <新的名字>`，它只读取电源事件；其他平台直接运行 `node tools/motion-active-perf.ts --name=<新的名字>` 并独立记录电源条件。浏览器本机路径见 handoff。

`-SourceRoot .npm-cache/v1b-review-ace1c41 -Cases "reviewed-calm-end,reviewed-frenzy-end"` 复现 reviewed 对照；`-SourceRoot .npm-cache/v1b-de-before-aa2cc8d` 为优化前的独立 Git 导出构建。不要 reset 当前工作区。`-PaintProbe no-grain -Browsers "firefox,webkit"` 仅复现诊断，不能代替正式运行。`--profile --browsers=chrome --rates=4 --case=frenzy-end --name=<新的名字>` 保存单独 CPU profile，profile 的时长不计作正式帧验收。
